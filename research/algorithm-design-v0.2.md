# DriveEvidenceLab 算法设计方案 v0.2

- 作者：算法工程师（agent=algo-engineer, model=GLM-5.3）
- 状态：设计草案（未含任何已完成实验结果；未验证内容均标注"待验证假设"）
- 修订：v0.2 针对 Round 2 审查（review-algorithm-design-v1.md）落实 M1-M3、吸收 S1-S8；v0.1 原文保留不动
- 目标：为自动驾驶仿真中的接管/冲突/事故事件，生成可回放、可审计的"证据链"，并做事件归因。

## 1. 研究问题定义

**形式化问题陈述**：给定一次仿真 rollout 产生的时序状态流 S 与事件 e（接管/冲突/事故），
求证据链 C 与归因评分函数 A，满足三项可证伪判据：

1. **归因正确性**：A(C, e) 对评价用 ground truth（场景注入变量 z_e，代理真值，见 §2）排序准确；
2. **证据完整性**：C 覆盖导致 e 的最小充分因果因素集（最小性）；
3. **回放一致性**（依赖 R1 缓解措施成立，见 §7）：以 C 中状态序列驱动回放可复现 e
   （误差有界；因仿真器存在非确定性，采用容差判据而非严格确定性回放）。

**难点**：仿真状态高维、多智能体耦合、因果混杂（待验证假设：场景脚本可提供反事实干预接口，从而注入变量可枚举、可干预）。

## 2. 核心概念与数据结构：EvidenceChain

设时间步 t ∈ {0,…,T}，智能体 i ∈ {1,…,N}。

- **状态快照** s_t = (ego 态, 众包他车态, 道路/交通灯态, 天气与传感器噪声参数)。固定频率 f_s
  采样 + 事件触发式加密（待验证假设：f_s ≥ 10 Hz 时关键动态不丢失，需实验标定）。
- **事件** e = (类型, t_e, 涉及智能体集 V_e, 严重度, 场景注入变量 z_e)。z_e 由场景脚本给出，
  **作为评价用 ground truth（代理真值）**——其因果有效性为待验证假设（注入变量 ≠ 真实因果，
  见 §7-R2，由专家抽检协议部分缓解）。
- **因果链接** l = (源 c_s, 目标 c_t, 类型 τ, 强度 w)，τ ∈ {物理触发, 决策触发, 环境触发}。

**EvidenceChain 定义**：C = ⟨ (s_{t0},…,s_{tk}), e, L, M ⟩
- (s_{t0},…,s_{tk})：场景种子状态到事件时刻的稀疏状态序列（关键帧 + 触发帧）；
- L = {l}：因果链接集合，节点为状态片段或行为决策；
- M：元数据（场景 ID、随机种子、仿真器版本与校验和、采样配置），**旨在支持**
  可审计与可复现；完整可复现还依赖代码与环境锁定（见 §5），故不表述为"保证"。

## 3. 算法框架（四层）

### L1 状态记录与采样层
- 固定频率环采 + 事件窗口自适应加密；状态规范化为封闭模式（schema 校验）。
- 决策层日志单独记录（待验证假设：决策日志与状态流时间轴可对齐，误差 < 1 步长）。

### L2 事件检测层
- 规则检测器（TTC < 阈值、碰撞、接管信号）+ 学习检测器（异常检测，备选）双通道，
  以 (类型, 置信度) 输出并触发 L1 加密采样与 L3 构建。

### L3 证据链构建层
- 以 e 为锚点，反向时间窗提取候选节点；剪枝保留对 e 预测误差贡献超阈值 δ 的
  节点（待验证假设：该准则与最小因果集近似等价）；输出 DAG 结构。

### L4 因果归因评分层
- Granger：G(x→y) = log[ MSE(y|历史(剔除x)) / MSE(y|全历史) ]；SCM 反事实：
  A(z) = I(e 发生|z=实际值) − I(e 发生|z=基线值)（多次重复取频率估计）；
- 综合：Score(c) = α·G + β·A + γ·T，T = exp(−λ(t_e − t_c))；α/β/γ/λ 为待标定
  超参（待验证假设：标定集上网格/Bayes 优化）。
- **逐层消融矩阵（S3）**：L1 采样频率（f_s ∈ {5,10,20} Hz）、L2 单/双通道、L3 阈值 δ 扫描、
  L4 分量（去 G / 去 A / 去 T）；每配置同步报告计算量与端到端时延（相对全配置比值）；消融预算与主实验相同。

## 4. 实验设计（计划，无任何已执行结果）

**数据与协议**：仿真器（选型待定：CARLA / 自研，待验证假设：提供确定性重放与
变量注入接口）。
**场景集划分（S6）**：按场景 ID 分层随机划分为标定/验证/测试三集（比例随功效
分析确定），另保留未见分布集（held-out：新地图簇、未见天气-光照组合）；四类
划分随场景集版本冻结（版本号+日期+SHA-256 校验和记入 M）。
**种子策略（S5）**：随机源分三类——场景内容种子（固定）；仿真扰动种子（逐 rollout 独立变化，
每场景 R 个独立种子，R 待功效分析确定，独立种子数随结果公开）；算法随机性种子（固定 1 枚并报告）。

**对比基线（S1，固定，不再标"候选"）**：
1. B0 朴素下界：时间最近性归因（取事件前最近异常）；B1 纯 Granger（无反事实）；
   B2 纯反事实消融（无时序评分）；B3 端到端学习归因（黑盒，可解释性下限参照）；
2. **Oracle 上界**：以注入真值为归因参照，仅用于标定评分上界，不入对比表。
公平性声明：所有基线共享同一场景集划分、同一计算预算上限（反事实重跑次数与
训练轮数对齐）、同一标定集调参。

**评价指标（S2，预声明主/次）**：
- **主指标**：归因 Top-1 准确率（命中评价用 ground truth 注入变量）；
- 次指标：Top-3 命中率（平局按归因分排序、再平局按变量注入时间先后）；证据
  完整性（关键因果节点召回 + 冗余节点比例）；回放一致性（事件复现频率 ≥ 1−ε；
  状态轨迹偏差 ADE/FDE，单位米）。
- ε 确定方法：以 oracle 回放试点估计"注入基线值时事件不发生"比例的 2 倍标准误
  为容差上限（试点后冻结；此方法本身为待验证假设）。
- "关键因果节点" ground truth 定义：注入变量触发链上的场景脚本节点（脚本生成器自动标注，
  10% 人工抽检）；聚合 macro 为主、micro 辅助；"事件未复现"计入回放一致性失败，不剔除样本。

**统计设计要点**：
- 功效分析：目标效应量为比例差（Top-1 提升 ≥ 0.10），α=0.05、power=0.8，两
  配对比例检验反推每基线场景数 n，试点方差代入；效应量报告用 Cohen's h 与
  风险差 RD（S4，不与 Cohen's d 混用）。
- 检验前提与备选（S4）：配对比例检验需个体比例近似正态（np≥5）；不满足时改用
  McNemar 精确检验或置换检验（10^4 次），选型理由随结果公开。
- 多重比较（S4）：主指标单一且属确证性 → Holm-Bonferroni 控制 FWER；次指标
  多域且属探索性 → 辅以 BH 控制 FDR；比较族大小随基线×指标矩阵预先声明。
- 报告效应量与 95% CI，不唯 p 值。

**混杂因素控制（M1）**——潜在混淆变量清单与控制手段（逐项）：

| 混淆变量 | 控制手段 |
|---|---|
| 场景类型 / 地图簇 | 分层随机划分 + 作为分层报告因子 |
| 事件严重度 | 分层（轻/中/重）报告 + 回归调整（入协变量） |
| 涉及智能体数 | 约束采样（各层配额）+ 回归调整 |
| 天气与光照 | 约束采样（组合配额）+ 分层报告 |
| 事件时刻背景流量 | 回归调整（入协变量） |
| 检测器通道（规则/学习） | 配对设计（同一 rollout 双通道配对比较） |

**分工声明（M1）**：上表手段控制可列名混淆变量对组间比较造成的偏倚；混合效应
模型/分层 bootstrap 仅处理场景间相关性（同一地图簇内 rollout 非独立）导致的方差
低估——两者互补、不可互相替代（混合效应随机截距按地图簇/场景 ID 嵌套；方法
选型为待验证假设）。

## 5. 可复现性工程计划（M2/M3；均为规划，无一实施）

**仓库结构与一键运行入口（M2）**（规划）：
```
DriveEvidenceLab/
  research/           # 设计文档（本目录）
  src/                # 源码（L1-L4 各层一子包）
  scenarios/          # 场景集 + 版本 + 校验和清单
  configs/            # 每次实验一个 YAML 配置（种子、版本、超参）
  scripts/run_all.sh  # 一键运行入口（仿真→检测→构建→归因→报告）
  results/            # 每实验一子目录（配置快照 + 日志副本 + README）
  logs/               # 运行日志（append-only）
```
提交约定：结果目录与生成它的代码 commit、配置文件三方绑定；入口脚本纳入版本控制。

**运行日志规范（M2）**：每次运行逐条记录——配置文件哈希、全部随机种子、仿真器版本与校验和、
代码 commit 哈希、依赖清单哈希、起止时间、硬件占用摘要；日志 append-only，随结果归档。

**文档-代码-结果对应（M2）**：可实验断言逐一编号（如 H-fs10、H-prune-min）；代码标记关联
断言编号；结果目录 README 反向引用——形成"文档断言 ↔ 代码 ↔ 结果"三向可追溯。

**环境锁定计划（M3）**：
- 仿真器：固定版本，记录安装包 SHA-256 校验和（CARLA 记录发布版本号）；
- 依赖：优先提供锁定版本的容器镜像（Dockerfile + 镜像 digest 双记）；无容器
  条件下用 requirements.txt 精确版本 + pip freeze 快照；
- 硬件：CPU/GPU 型号与数量、显存、驱动与 CUDA 版本随日志归档；
- 关键库（物理引擎、数值库）版本影响说明方式：pilot 阶段做单变量版本扰动测试
  （各升一档），受影响指标写入 results/ENV_SENSITIVITY.md（规划）。

## 6. sim-to-real 声明与分布偏移（S7）

- **声明**：本文一切指标均为仿真环境内指标，不得表述或外推为实车/真实道路性能；
  仿真回放一致性 ≠ 实车可复现性。
- **分布偏移预报告计划**：主测试集与未见分布集的性能差为预先登记报告项；偏移来源记录：
  地图簇、天气-光照组合、智能体密度、场景脚本生成参数（原文存档）；外推影响方向试点前预登记、后不得追改。

## 7. 风险与开放问题

- R1 仿真器非确定性：固定种子 + 容差回放判据（有效性待验证）。
- R2 代理真值局限：z_e 为评价用代理真值，需专家抽检协议（比例与合格线待定）。
- R3 评分融合过拟合：留出验证 + 交叉验证。
- R4 反事实计算成本：预算约束下的采样策略为开放问题。
- R5 跨场景泛化：归因超参场景无关性为开放问题（以未见分布集检验）。
- R6 证据链隐私脱敏：发布数据脱敏标准未定（开放问题）。
