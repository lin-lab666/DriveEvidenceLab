# DriveEvidenceLab 算法设计方案 v0.1

- 作者：算法工程师（agent=algo-engineer, model=GLM-5.3）
- 状态：设计草案（未含任何已完成实验结果；未验证内容均标注"待验证假设"）
- 目标：为自动驾驶仿真中的接管/冲突/事故事件，生成可回放、可审计的"证据链"，并做事件归因。

## 1. 研究问题定义

**形式化问题陈述**：给定一次仿真滚动（rollout）产生的时序状态流 S 与一个事件 e（接管/冲突/事故），
求一个证据链 C 及归因评分函数 A，使得：

1. **归因正确性**：A(C, e) 对事件真因（由仿真场景脚本的注入变量定义 ground truth）排序准确；
2. **证据完整性**：C 覆盖导致 e 的最小充分因果因素集（最小性）；
3. **回放一致性**：以 C 中状态序列驱动确定性回放，可复现 e（误差有界）。

**难点**：仿真状态高维、多智能体耦合、因果混杂（待验证假设：场景脚本可提供反事实
干预接口，从而 ground truth 因果可枚举）。

## 2. 核心概念与数据结构：EvidenceChain

设仿真时间步 t ∈ {0,…,T}，智能体 i ∈ {1,…,N}。

- **状态快照** s_t = (ego 态, 众包他车态, 道路/交通灯态, 天气与传感器噪声参数)。
  建议以固定频率 f_s 采样 + 事件触发式加密采样（待验证假设：f_s ≥ 10 Hz 时
  关键动态不丢失，需实验标定）。
- **事件** e = (类型, t_e, 涉及智能体集 V_e, 严重度, 场景注入变量 z_e)。
  z_e 由场景脚本给出，构成归因 ground truth。
- **因果链接** l = (源 c_s, 目标 c_t, 类型 τ, 强度 w)，τ ∈ {物理触发, 决策触发, 环境触发}。

**EvidenceChain 定义**：C = ⟨ (s_{t0},…,s_{tk}), e, L, M ⟩
- (s_{t0},…,s_{tk})：从场景种子状态到事件时刻的稀疏状态序列（关键帧 + 触发帧）；
- L = {l}：因果链接集合，节点为状态片段或行为决策；
- M：元数据（场景 ID、随机种子、仿真器版本、采样配置），保证可审计与可复现。

## 3. 算法框架（四层）

### L1 状态记录与采样层
- 固定频率环采 + 事件窗口内自适应加密；状态规范化为封闭模式（schema 校验，防漂移）。
- 决策层日志（规划/控制的关键决策点）单独记录（待验证假设：决策日志与状态流
  时间轴可对齐，对齐误差 < 1 步长）。

### L2 事件检测层
- 规则检测器（TTC < 阈值、碰撞、接管信号）+ 学习检测器（异常检测，备选）双通道，
  事件以 (类型, 置信度) 输出并触发 L1 加密采样与 L3 构建。

### L3 证据链构建层
- 以事件 e 为锚点，反向时间窗内提取候选节点；
- 候选剪枝：保留对 e 的预测误差贡献超过阈值 δ 的节点（消融式剪枝，待验证假设：
  该准则与最小因果集近似等价）；
- 输出 DAG 结构的 EvidenceChain。

### L4 因果归因评分层
- **时序先行性（Granger 因思路）**：对候选因子 x 与事件代理量 y，
  G(x→y) = log[ MSE(y | 历史(剔除 x)) / MSE(y | 全历史) ]。
- **结构因果模型（SCM）思路**：以场景注入变量 z 为可干预外生节点，反事实评分
  A(z) = I( e 发生 | z = 实际值 ) − I( e 发生 | z = 基线值 )，I 为指示函数（多次
  重复取频率估计）。
- **综合评分**：Score(c) = α·G(c) + β·A(c) + γ·Timeliness(c)，
  Timeliness(c) = exp(−λ(t_e − t_c))；α, β, γ, λ 为待标定超参（无先验实验数据，
  全部为待验证假设，需在标定集上网格/Bayes 优化）。

## 4. 实验设计（计划，无任何已执行结果）

**数据与协议**：仿真器（选型待定：CARLA / 自研，待验证假设：提供确定性重放与
变量注入接口）；每场景重复 R 次以估计事件频率方差（R 待功效分析确定）。

**对比基线（候选）**：
1. 纯时间最近性归因（取事件前最近异常）；
2. 纯 Granger 因果（无反事实）；
3. 纯反事实消融（无时序评分）；
4. 端到端学习归因（黑盒，可解释性下限参照）。

**评价指标**：
- 归因准确率：Top-1 / Top-k 命中 ground truth 注入变量（k=1,3）；
- 证据完整性：召回的关键因果节点比例 + 链最小性（冗余节点比例，越低越好）；
- 回放一致性：回放复现事件的频率（目标 ≥ 1 − ε，ε 待定）与状态轨迹偏差（ADE/FDE）。

**统计设计要点**：
- 样本量功效框架：给定目标效应量 d（如归因准确率提升 ≥ 0.10）、α=0.05、
  power=0.8，两配对比例检验反推每基线所需场景数 n；以小规模试点估计方差后代入。
- 多次比较校正：多基线 × 多指标统一用 Holm-Bonferroni 或 Benjamini-Hochberg
  控制 FWER/FDR（阈值随比较族大小校正）。
- 报告效应量与置信区间，不唯 p 值；场景间相关性（同地图簇内）用混合效应模型或
  分层 bootstrap（方法选型为待验证假设）。

## 5. 风险与开放问题

- **R1 仿真器非确定性**：随机种子与物理引擎浮点非确定可能破坏回放一致性
  （缓解：固定种子 + 容差回放判据；有效性待验证）。
- **R2 ground truth 局限**：注入变量 ≠ 真实因果（场景设计偏差），需专家抽检协议。
- **R3 评分函数融合**：α/β/γ 无先验，可能过拟合标定集（缓解：留出验证 + 交叉验证）。
- **R4 反事实次数成本**：SCM 评分需多次重跑，计算预算约束下的采样策略是开放问题。
- **R5 跨场景泛化**：归因超参是否场景无关（开放问题）。
- **R6 可审计性 vs 隐私**：证据链若含他车轨迹，发布数据的脱敏标准未定（开放问题）。
