# DriveEvidenceLab 科研审查清单 v1

- 文档性质：研究审查标准（方法学 / 统计 / 可复现性 / 结论有效性），不依赖任何实验数据
- 版本：v1 | 建立轮次：Round 1 | 适用范围：本项目全部提交的实验设计与结论
- 审查独立性：审查员独立于算法工程师与编程工程师，仅依据提交材料与公开方法学标准作出判断

## 一、实验方法学审查

| # | 审查点 | 0 分（严重缺陷） | 3 分（达标） |
|---|--------|------------------|--------------|
| 1.1 | 研究问题明确性 | 问题模糊、不可证伪、无判定标准 | 研究问题可证伪，范围与输入输出、判定标准预先成文 |
| 1.2 | 基线合理性 | 无基线，或基线被刻意弱化、配置不对等 | 覆盖领域公认基线，参数/数据预算公平；必要时含上界（oracle）与朴素下界 |
| 1.3 | 指标定义严谨性 | 指标口径混乱、缺单位与边界定义、事后更换指标 | 每个指标给出公式、单位、边界情形与聚合方式；主指标/次要指标预先声明 |
| 1.4 | 混杂因素控制 | 未识别混淆变量，对比组条件不可比 | 显式列出潜在混淆变量，并说明控制手段（分层、配对、回归调整、约束采样） |
| 1.5 | 消融设计 | 无消融，或多模块改动纠缠、归因不清 | 逐模块消融，增量归因清晰，同时报告计算量与时延成本变化 |

## 二、统计设计审查

| # | 审查点 | 0 分（严重缺陷） | 3 分（达标） |
|---|--------|------------------|--------------|
| 2.1 | 假设检验选择依据 | 未说明检验方法，或违反检验前提直接套用 | 说明所选检验及其前提（正态性、方差齐性、配对性）；前提不满足时改用非参数或置换检验 |
| 2.2 | 多重比较校正 | 多组/多指标比较未校正，p 值被择优使用 | 存在多重比较时使用 Bonferroni、Holm 或 FDR 等校正并说明选择理由；单一主对比也应显式声明 |
| 2.3 | 功效分析与样本量论证 | 无样本量说明，"跑几次看结果"事后补样 | 基于预期效应量与目标功效给出最小试验/场景数；不得为达显著而追加样本后重算 |
| 2.4 | 效应量与置信区间报告 | 仅报均值、准确率或 p 值 | 报告效应量（如 Cohen's d 等标准化均值差）与置信区间；结论以区间而非单点数值表述 |

补充：若结论包含因果主张（如"某设计导致安全性提升"），须区分相关与因果。可借助因果推断框架表述，例如结构因果模型（SCM）将因果关系表示为变量、外生噪声与结构函数的图结构，并通过干预与反事实进行推断；Granger 因果检验基于时间顺序上的预测增益判断统计因果性。使用时应声明各自假设与局限，不得将统计关联直接表述为因果。

## 三、可复现性审查

| # | 审查点 | 0 分（严重缺陷） | 3 分（达标） |
|---|--------|------------------|--------------|
| 3.1 | 随机种子 | 种子未固定，或按结果挑选种子/运行次数 | 所有随机源固定种子，报告独立种子数量；重跑结果一致或在声明容差内 |
| 3.2 | 数据/场景版本 | 数据来源、版本不可追溯 | 记录数据集与场景生成器版本、日期与校验和；明确划分训练/测试/未见分布 |
| 3.3 | 代码可运行性 | 代码无法运行，或缺关键脚本与依赖清单 | 提供一键运行入口与运行日志；代码按约定提交（公开仓库或项目私有库） |
| 3.4 | 环境锁定 | 环境不可复现，缺依赖与硬件记录 | 依赖清单或容器镜像锁定版本；记录硬件差异及关键库版本对结果的影响 |

## 四、结论有效性审查

| # | 审查点 | 0 分（严重缺陷） | 3 分（达标） |
|---|--------|------------------|--------------|
| 4.1 | 结论与证据匹配度 | 结论超出数据支持范围，或引用未做过的实验 | 每条结论可回溯到具体指标、检验与图表，无证据悬空 |
| 4.2 | 过度概括检查 | 由仿真结果直接断言实车性能、由场景库外推到开放世界 | 概括范围严格限定于测试分布；未测条件显式声明"未验证" |
| 4.3 | 不确定性表述 | 只报正面结果，隐去失败案例与局限 | 报告负面/异常结果；列出威胁结论有效性的局限及其影响方向 |

## 五、评分标准

- 计分：每个审查点 0-3 分（0=严重缺陷，1=重大不足，2=基本达标，3=达标）。
- 维度分 = 维度内审查点均分；总分 = 四个维度均分（各维度权重 25%，满分 3 分）。
- 通过门槛：总分 ≥ 80%（即 2.4/3），且无任何审查点为 0 分。
- 意见分级：
  - 【必须修改】存在以下任一情形：审查点为 0-1 分；捏造或不可复现；统计误用可能导致结论反转；结论无证据支撑。
  - 【建议修改】审查点为 2 分，报告规范性或表述严谨性可提升，但不影响核心结论。
- 复审机制：凡标注"必须修改"的条目，下一轮须提交修订说明；审查员仅复核修订部分及受影响结论。

## 六、自动驾驶仿真研究特别注意事项

1. sim-to-real 差距声明：凡以仿真作为证据，须显式声明保真度假设（传感器模型、车辆动力学、通信与执行时延）；不得将仿真指标表述为实车指标。
2. 场景分布偏移：须报告场景分布与目标分布的差异来源（生成方式、背景交通行为模型、长尾覆盖程度），并说明其对结论外推的影响方向。
3. 场景库代表性与版本：记录场景集版本与生成参数；安全关键结论须补充分布外场景的鲁棒性证据。
4. 反应式交通模型声明：背景车行为若采用基于跟驰模型（如 IDM 一类经典模型）的反应式假设，须声明其局限，不得将行为模型假设当作真实交通规律。
5. 安全指标口径：碰撞率、接管率、TTC 等安全指标的统计口径（每公里/每场景/每次交互）须全文统一并显式说明。
6. 随机交互重复性：涉及多智能体随机交互时，报告独立重复次数与结果波动范围；禁止只展示最佳单次运行。
7. 闭环与开环声明：区分闭环仿真与开环回放（log-replay）结论，两者不可互相替代佐证。
