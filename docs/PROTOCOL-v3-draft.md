## 1. "独立动力学"的最低标准

一个后端只有在同时满足下列四条时，才算 v3 意义上的独立动力学：

1. **运动方程由第三方实现**：纵向/横向运动、跟驰或换道决策至少有一层来自外部引擎，
   而不是本项目 `sim/builtin.py` 的循环。
2. **碰撞/越界判定由第三方几何或引擎事件给出**，或由本项目独立复核后与引擎事件比对。
3. **同一初始条件可确定性重放**（引擎须支持固定随机种子 + 固定步长，或明确其非确定性并提供
   重复次数与离散度报告）。
4. **能力边界显式声明**：`capabilities()` 必须如实反映该引擎支持/不支持哪些 IR 特征，
   不得用近似映射假装支持。

第 3 条最容易失败：多数交通仿真器的默认行为含随机性与并行调度，若不做确定性配置，
"重放一致"这一 T1 前提直接不成立。

## 3. v3 必须先定义的东西（预注册要素）

### 3.1 引擎与版本钉死

```
engine = Eclipse SUMO
version = <精确版本，含 build 号>
car_following_model = Krauss（含参数表）
lane_change_model = LC2013（含参数表）
step_length_s = <固定值>
seed_policy = <固定 master seed 集，逐 episode 派生规则>
```

### 3.2 场景映射与保真度分级

必须为每个 IR 字段标注映射等级，并**在运行前**写死：

| IR 字段 | SUMO 对应 | 保真度 |
|---|---|---|
| 道路长度 / 车道数 / 车道宽 | net 生成参数 | 精确 |
| 限速 | `speedLimit` | 精确 |
| ego 初始位置/速度 | `route` + `departSpeed` + `departPos` | 精确 |
| 前车初始间距/速度 | 第二辆车 + `departPos` | 精确 |
| 纵向加速度上限 | `accel` / `decel` | **近似**（SUMO 用跟驰模型，不直接受 IR 的加速度约束） |
| 横向偏移 | `departPos` 的 lateral 分量（若版本支持） | **可能不可表达** |
| 规划器 `safe_follow` | 见 §3.3 | **无法直接迁移** |

任何标为"近似"或"不可表达"的字段，都必须在结论里显式降级适用范围。

### 3.3 规划器可比性（v3 最大的设计难题）

跨引擎比较"同一个规划器"在原理上不成立：规划器消费的是引擎内部状态（前车距离、相对速度），
不同引擎的状态语义、更新顺序、时延都不同。v3 必须在运行前二选一：

- **方案 P1（行为对照）**：两边都用**各自引擎的原生跟驰模型**（builtin 用 `safe_follow`，
  SUMO 用 Krauss）。这比较的是"两种驾驶行为模型"，**不是**"同一算法在两个引擎里"。
  结论只能表述为"某类场景在不同行为模型下的失效复现率"。
- **方案 P2（控制器搬运）**：把 `safe_follow` 作为外部控制器，通过 TraCI 逐步写入 SUMO 的
  ego 加速度，前车由 SUMO 原生模型驱动。这时 ego 行为一致、环境动力学不同，
  但**必须**声明"ego 侧动力学仍受控制器更新频率与 SUMO 步长耦合影响"。

**推荐 P2**：它更接近"同一策略、不同动力学"，且能复用现有候选集。
但 P2 的代价是 ego 侧不再是纯第三方动力学，只有他车与环境是——这一点必须写进结论限制。

### 3.4 预算与记账

- 沿用 v2 口径：`launched = completed + failed + cancelled + infeasible ≤ max_episodes`，
  两次引擎调用都要入账，失败与超时不得从分母剔除。
- 候选集必须是 v2.1 的**同一批** 128 个候选（每方法 64），否则无法与 v2.1 对照。
- 引擎侧崩溃必须单独计为 `simulator_error`，不得混入 `timeout`。

### 3.5 指标与判定规则（必须在运行前写死）

主指标：**跨引擎失效复现率** = 在 v2.1 中判为"稳定失效"的候选中，
在 SUMO 下仍被判为同类失效的比例。

预注册判定（草案，冻结时定稿）：

- **H4-v3（跨引擎复现）**：`cross_engine_reproduction_rate` 的 Wilson 95% 下界 > 0.5。
- **H5-v3（引擎间差异）**：两引擎失效率的 Newcombe 95% CI 不含 0（方向不预设）。
- 多重比较：H4/H5 与 v2 的 H1–H3 不构成同一检验族（不同数据），单独报告，
  不得回头修正 v2 的结论。

### 3.6 失效判据的语义对齐（必须逐条核）

| 类别 | builtin 定义 | SUMO 下的等价物 | 对齐风险 |
|---|---|---|---|
| COLLISION | 矩形间距 ≤ 阈值 | `collision` 输出 / 安全距离 | 阈值定义不同 |
| OFF_ROAD | 中心点出 lanelet 并集 | 车辆离开车道 + 越界标志 | 边界判定不同 |
| NEAR_MISS | min_gap 与 min_ttc 同时低于阈值 | 需自行从 TraCI 采样计算 | 采样频率影响 TTC |
| RULE_VIOLATION | 超速 | `speedLimit` 违规检测 | 单位/容忍带 |
| TIMEOUT | 达 `max_steps` | 达仿真终止时间 | 步长不同导致不等价 |

**没有对齐表的跨引擎比较是无效的**——这是 v3 与 Gate D 已完成部分的本质区别。

## 4. v3 能支持与不能支持的结论

**能支持**
- "在 `safe_follow` 策略下，v2.1 认定的稳定失效中，有 X% 在第三方跟驰模型下仍然出现。"
- "两引擎的失效率差异为 Δ（含 95% CI），是否可检出。"

**不能支持**
- 任何真实道路结论。
- "结论与仿真器无关"——只测了**一个**额外引擎。
- "两引擎等价"——CI 跨 0 只能说未检出差异。
- 把 SUMO 的绝对失效数当作"更真实"的基准。SUMO 也是模型。

## 5. 与 v2 的关系

- v2 的 H1–H3 结论**不因 v3 而改变**。v3 是独立的新数据、新假设族。
- 若 v3 发现跨引擎复现率很低，正确解读是"v2 的结论高度依赖 `builtin` 运动学"，
  这**不会**推翻 v2 在其声明范围内的有效性，但会显著缩小其适用范围。
- v3 必须在运行前冻结；**不得**看到 v2.1 的 57/64 与 61/64 之后再去调阈值使其"好看"。
