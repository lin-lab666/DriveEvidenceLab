# DriveEvidenceLab｜已知局限与适用边界

> 版本：对应 `driveevidence 0.2.0`（Gate E v2.1 结果）
> 目的：把"这个项目**不能**支持什么"集中写清楚，避免结论被引用到证据范围之外。
> 相关文档：`docs/SCIENTIFIC_AUDIT.zh-CN.md`（审计细节）、`docs/GATE_D.zh-CN.md`（第二仿真系统）、
> `docs/DECISIONS.md`（逐条决策与缺陷记录）。

本文按"结论会被怎样误用"来组织，而不是按模块组织。

---

## 0. 三层结论状态（先看这个）

| 层级 | 含义 | 当前状态 | 一句话 |
|---|---|---|---|
| **T1 内部一致性** | 产物之间自洽；报告里每个数字都能从原始数据重算；归档 episode 能逐位重放 | **15/15 通过** | 可以相信"文件没被篡改、数字没算错" |
| **T2 方法学有效性** | 测量工具真的测到了协议声称的东西 | **v2.1 通过，保留 1 项 FAIL** | 可以相信"这次测的是稳定性"，但不能相信"任意带宽下都如此" |
| **T3 外部独立复现** | 独立第三方在独立环境复现 | **不具备** | **不能**说"结论已被独立验证" |

**T1 通过不等于 T3 通过。** 哈希链完整只证明记录未被篡改，不证明实验设计正确，
更不证明结论在别处成立。三者混用是本项目最容易被误读的地方。

## 1. 仿真器局限

| 局限 | 具体内容 | 影响 |
|---|---|---|
| 运动学模型 | `builtin` 是无动力学约束的运动学模型（IDM-lite 跟驰 + 横向偏移），**没有**轮胎侧偏、悬架、制动延迟、执行器饱和 | 碰撞/近失的**时刻与位置**不可外推到真实车辆 |
| 无物理引擎 | 没有刚体动力学或接触求解；碰撞判定是几何间距阈值 | "collision" 的含义是"间距 ≤ 阈值"，不是"发生了物理碰撞" |
| 无传感器 | 无相机/激光雷达/噪声/延迟建模；感知是完美的 | 任何关于感知失效的结论都不适用 |
| 单一规划器 | 正式实验只用 `safe_follow`（规则型） | 结论**不外推**到 RL 规划器、MPC、或任何其他控制器 |
| 无天气/路面变化 | 摩擦系数、能见度恒定为理想值 | 不适用于低附着、雨雾等场景 |

**明确禁止的表述**：不得称本项目的结果为"真实道路验证"、"实车验证"或"安全认证依据"。

## 2. 场景族局限

正式实验（Gate E）覆盖的场景族极窄：

- **单前车**、**直道**、**3 车道**、长度 500 m、限速 33 m/s、`max_steps=80`。
- 无切入（cut-in）、无多前车交互、无变道博弈、无路口、无环岛、无行人/非机动车、无施工区。
- `OFF_ROAD` 与 `RULE_VIOLATION` 在该族内**结构性罕见**：LR 横向偏移带宽只有 ±0.15 m，
  远小于车道半宽 1.85 m；限速 33 m/s 也高于 ego 初始速度上限。
  实际统计中，失败类别近似为"碰撞 + 近失 + 超时"三类，**不是**四类。任何"四类失败均已覆盖"
  的说法都不成立。

**后果**：高稳定率（0.89 / 0.95）**只说明**"这些失效对协议规定的 ε 扰动稳健"，
**不说明**"系统在该场景族中普遍失效"，更不说明"真实世界中会失效"。

## 3. 稳定性度量的局限

| 问题 | 说明 |
|---|---|
| ε 带宽是人为选定的 | ego 速度 ±2.0 m/s、横向 ±0.15 m、前车间距 ±3.0 m、前车速度 ±1.5 m/s、3 次扰动中 ≥2 次复现。换带宽会换数值；本协议只对当前带宽负责 |
| "稳定"是离散判据 | 判据是"同类别复现 ≥2/3"，不是连续量。2/3 与 3/3 在指标上等价，会损失信息 |
| 扰动保持结构 | 只改初始条件，不改车道数/几何/车辆数。**结构性失效**（如"该场景必然碰撞"）不会被扰动检出，会被稳定地判为稳定 |
| 20 个种子服务 64 个候选 | 跨候选复用扰动种子（每个约用 9.6 次）。"独立"只在**同一候选的 3 次之间**成立 |
| 高稳定率可能来自场景本身 | 若提名集合中的场景普遍处在"碰撞不可避免"的临界区，任何微扰都会复现失效。本协议**无法区分**"失效稳健"与"场景必然失效" |

最后一条是当前设计最大的解释性缺口，需要引入**可恢复场景对照**（同一场景在轻微减速下应转为不失效）
才能缓解，本版本未实现。

## 4. 统计局限

| 问题 | 说明 |
|---|---|
| 样本量 | 每方法 64 个实测候选。H2 的观测差异 Δ=+0.0625，Newcombe 95% CI [−0.0365, +0.1668] 跨 0 |
| **H2 是"未检出"不是"无差异"** | 64 对样本对 6 个百分点的差异**功效不足**。正确表述是"没有可检出的差异"，**不是**"两方法等价" |
| 多重比较 | H1/H2/H3 构成检验族，用 Holm 校正（FWER 0.05）。校正后 H1 p=9.03e-49、H3 p=0.001、H2 p=0.324 |
| H1 的 p 值口径 | H1 的**判定规则**是 Wilson 下界 > 0.1，不是 p 值。Holm 记账时用单侧二项尾概率，属辅助量 |
| H3 的 bootstrap p | 百分位 bootstrap 只给区间；记账用的 p=1/B=0.0005 是分辨率下限，不代表真实 p 恰为此值 |
| Wilson 的 z | 项目统一用 z=1.96（而非精确分位 1.959964），差值 ~3e-6，不影响任何判定 |
| 搜索 RNG 耦合 | 两方法在 archive 为空时共用同一 `default_rng(master_seed)` 流。实测逐种子重合 min=1/median=16/max=64，**4/64 对完全退化**（seed 2100/2138/2144/2161），名义 64 个独立配对实际少于 64 |
| 耦合的因果解释 | 重合会使配对差值向 0 收缩，这是**机制性解释**，不是已证明的偏差方向。分层结果（剔除退化 +0.3914、低重合 +0.5096、高重合 +0.2330，各层 CI 均排除 0）只支持"方向稳健"，**不支持**"合并估计必然保守"——分层是对同一数据的事后重组，不构成因果识别 |

## 5. 协议修订史（必须完整披露）

| 版本 | 状态 | 发生了什么 |
|---|---|---|
| **v1** | 稳定性结论**已撤回** | `builtin` 创建 `rng` 后从未使用 → episode seed 零效果；1716/1716 候选在 3 个"独立"种子下逐位相同。`stable yield = 100%` 是同义反复。主指标 `前16确认数/提名数` 退化为 `16/提名数`，度量的是提名量而非稳定性 |
| **v2.0** | 结果**降级为协议偏差**并列保留 | 修复 seed 语义（ε-扰动）后重跑，但随后发现 `builtin/1.0` 的 `for...else` 使 NEAR_MISS 分支不可达（16384 episodes 中 0 次 near_miss），失效分类塌缩为仅碰撞 |
| **v2.1** | **当前主结果** | 修复分类器（`builtin/1.1`）后重跑，near_miss 出现 57 次。random 0.890625 (57/64)、mutation 0.953125 (61/64) |

三套产物**全部保留**：`runs/formal_experiment_v1/`、`runs/formal_experiment_v2/`、
`runs/formal_experiment_v2p1/`。v1 的数字未被删除或改写，只是被标记为无效。

**v1 的 `discovery_yield` 仍然有效**（不依赖 episode seed 语义），可作为历史记录引用；
但 v1 的稳定性数值与 H1/H2 结论**一律无效**。

**关于 v1 协议哈希**：v1 文件内嵌的 `247f6721…` 与整文件 SHA-256 `9dcbd097…` 不一致，
且不等于任何可复现的计算约定（自指哈希在数学上不可实现）。该异常**永久保留**，
记为 T2 的唯一 FAIL，未做任何掩盖或"修正性"重写。

## 6. 可复现性局限

- **同作者、同代码库、同一台机器**产生全部产物。`runs/formal_experiment_v1`、
  `v2`、`v2p1` 都是。因此 **T3 未达成**。
- 证据束（`evidence/*.tar.gz`）是确定性打包（排序、`mtime=0`、`uid/gid=0`、gzip `mtime=0`），
  `scripts/build_evidence_bundle.py --check` 可验证重建结果一致。
- 但"包能重建"只证明打包过程确定，**不证明**实验结论在别的实现下成立。
- 公开仓库的 git 历史是**经过整理的单一提交**，不是完整研发历史；原始冻结提交无法仅靠
  公开仓库独立核验。协议正文哈希与证据校验和已独立保存，不依赖 git。

## 8. 不要这样引用本项目

以下表述均**超出证据范围**，在论文、README、宣传材料中都不应出现：

1. ❌ "DriveEvidenceLab 验证了自动驾驶系统的安全性。"
2. ❌ "失效在真实道路上也会复现。"（纯仿真，无实车）
3. ❌ "变异搜索比随机搜索更能发现稳定失效。"（H2 不支持；v1 的相反结论已撤回）
4. ❌ "mutation 与 random 的稳定性等价。"（是"未检出差异"，不是"等价"）
5. ❌ "四类失效均已覆盖。"（该场景族内结构性只剩碰撞/近失/超时）
6. ❌ "跨仿真器验证已通过。"（Gate D = PARTIAL，无第三方动力学）
7. ❌ "结果已被独立复现。"（T3 不具备）
8. ❌ "哈希链通过，所以实验为真。"（完整性 ≠ 有效性）
9. ❌ "改变扰动带宽后结论不变。"（未测）
10. ❌ "搜索 RNG 耦合已证明使结果保守。"（只有方向稳健性证据，无因果识别）

可以这样引用：

> 在 `builtin/1.1` 运动学仿真器、`safe_follow` 规则规划器、直道三车道单前车场景族、
> 协议 v2.1 规定的 ε 扰动带宽下，随机搜索提名的失效候选有 57/64 在扰动下复现
> （Wilson 95% CI [0.791, 0.946]）；变异搜索为 61/64（[0.871, 0.984]）；
> 两者差异未达统计显著（Newcombe 95% CI [−0.037, +0.167]）；
> 变异搜索的发现率显著更高（Δ=+0.367，[0.322, 0.412]）。
> 该结论未经外部独立复现。
