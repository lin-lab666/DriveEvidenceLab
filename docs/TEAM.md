# DriveEvidenceLab 多模型协作研发团队章程

> 版本：v1.0 | 生效日期：2026-10-19 | 总指挥：GLM-5.3

## 1. 项目定位

DriveEvidenceLab：自动驾驶仿真场景中"驾驶证据链"的采集、建模与归因研究。
目标：为仿真中的接管/事件/事故场景生成可回放、可审计的证据数据结构与研究方法。

## 2. 团队配置（角色 → 模型）

| 角色 | 花名 | 模型（Agent 工具 model 参数实传值） | 职责 |
|---|---|---|---|
| 总指挥 | team-lead（主智能体） | GLM-5.3 | 项目规划、任务拆分、协调、最终审核与验收 |
| 算法工程师 | algo-engineer | GLM-5.3 | 自动驾驶仿真算法、核心研究方案设计 |
| 编程工程师 | coding-engineer | DeepSeek-V4.1-Flash | 工程实现、模块开发 |
| 科研审查员 | research-reviewer | Step-5-Preview | 实验方法、统计设计、研究结论的独立审查 |
| 测试工程师 | test-engineer | DeepSeek-V4.1-Flash | 自动化测试、复现验证、CI |

说明：Agent Teams 实验性功能未开启，团队以"已验证的子智能体机制"运行——
总指挥通过 Agent 工具派发任务并显式传入模型 ID，成员通过工作区文件与共享任务清单协作。

## 3. 协作机制

1. **共享任务清单**：全部任务进入会话任务清单（TaskList 可见），状态由总指挥维护。
2. **工作区即协作面**：所有产物落盘 `D:/DriveEvidenceLab/`：
   - `research/` 研究方案与审查报告
   - `src/` 代码模块
   - `tests/` 测试套件
   - `logs/roundN/` 每轮协作日志证据（含各成员自报模型与时间戳）
   - `docs/` 团队章程与协作测试报告
3. **独立审查**：算法/研究类产物必须经科研审查员独立审查后方可定稿；审查意见与作者回应一并归档。
4. **验收机制**：代码必须经测试工程师运行真实测试（pytest）验收；禁止伪造实验数据、测试结果或科研结论。测试失败如实上报，不粉饰。
5. **模型可追溯**：每次派发必须显式传模型 ID；成员执行时在日志中自报模型，总指挥在报告中记录派发时间戳以验证并行性。

## 4. 异常处理

- **Step-5-Preview 限流（429）**：指数退避重试，最多 3 次（间隔约 30s/60s/120s）；仍失败则本轮降级为总指挥代行审查并在报告中明确标注"非独立模型审查"。
- **模型 ID 解析失败**：如实记录错误，不冒充、不换用后假装成功。

## 5. 权限边界

- 涉及付费资源、系统权限、GitHub 公开发布 → 必须先征得用户同意。
- 成员仅在 `D:/DriveEvidenceLab/` 内写文件，不触碰工作区外文件。

## 6. 会议节奏

按"轮（Round）"推进：每轮 = 并行生产 → 独立审查/测试 → 总指挥验收 → 归档 → 下一轮。
